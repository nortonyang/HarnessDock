## AT-401：隔离官方聊天与 Harness

用户故事 US-401：作为用户，我希望免费聊天与 Harness 是两个独立页面，以免登录状态、API Key 或工作区权限互相混用。

### 验收标准

- 官方 Chat 使用单独的 `WKWebView` 和协调器，不复用 Harness 的注入脚本或 localhost 导航策略。
- 应用不读取聊天 Cookie、登录表单、消息内容或内部 API。
- Harness API Key、余额数据和工作区路径不会注入聊天页面。

## AT-402：无损页面切换

用户故事 US-402：作为同时使用 Harness 与免费聊天的用户，我希望来回切换不会丢失正在运行的任务或聊天草稿。

### 验收标准

- 标题栏提供 `Harness` 与 `Chat` 分段入口，菜单提供 `⌘1`、`⌘2`。
- 免费聊天首次选择时才创建；创建后与 Harness WebView 同时常驻。
- 切换只改变显示、可访问性和命中测试，不销毁任一 WebView。

## AT-403：加载 DeepSeek 官方 Chat

用户故事 US-403：作为用户，我希望在应用内直接使用 DeepSeek 官方免费聊天的登录、消息和文件功能。

### 验收标准

- 顶层加载固定地址 `https://chat.deepseek.com/`，默认 WebKit 数据存储保留登录 Cookie。
- `deepseek.com` 及其子域主导航留在 WebView；其他站点在系统浏览器打开。
- 官网主动触发的文件选择支持单文件或多文件；应用不预先读取文件。
- 新窗口请求在同一 Chat WebView 或系统浏览器中安全处理。

## AT-404：加载状态和回退

用户故事 US-404：作为网络或风控异常下的用户，我希望能重试或改用 Safari，而不是停留在空白页面。

### 验收标准

- Chat 加载时显示轻量进度提示。
- 主导航失败时显示错误说明、“重载”和“在 Safari 中打开”。
- 切换到 Chat 时不影响 Harness 启动、停止和日志行为。
