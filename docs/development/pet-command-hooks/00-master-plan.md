# 总开发阶段文档：双页面宠物命令钩子

## 目标

让 DsHarness 的两套宠物都能响应正在执行的命令或消息任务：Harness Web 插件宠物订阅官方会话服务，Chat 原生宠物订阅 WebKit 页面生成状态。统一表现为运行时播放 `running`、成功后播放一次 `review`、失败后播放一次 `failed`，随后回到原有待机或鼠标交互状态。

## 非目标

- 不读取、保存或转发用户的提示词、回复正文、命令参数或工具输出。
- 不修改 DeepSeek Harness 官方包或 DeepSeek Chat 网页代码。
- 不新增动画素材，不改变已有贴边、点击穿透、拖动和宠物切换逻辑。
- 不把页面首次加载误当成一次用户命令。

## 当前证据

- Harness 插件已通过 `shell.overlay` 运行，客户端可注入官方 `sessions` 服务；其列表快照提供当前会话、`running` 和 `jobsBySession`。
- 当前会话绑定的快照提供 `running`、`promptError` 与 `lastAgentError`，可区分执行与新错误。
- Chat 原生宠物目前只根据网页导航加载与错误切换动画，不能感知回答生成。
- DeepSeek Chat 运行时会出现“停止生成/Stop generating”一类控件；WebKit 可用本地脚本消息桥只回传状态枚举。
- 两边现有 8×9 图集均已包含 `running`、`review` 与 `failed` 行。

## 假设与决策

- “两边”指 Harness 页面内的 Web 插件宠物与 Chat 页面内的原生宠物。
- 命令钩子覆盖普通提示、斜杠命令、工具运行和后台任务；不新增用户可输入的新命令。
- 状态优先级为失败/成功短反馈与运行状态高于自动探头，鼠标拖动机制本身保持可用。
- Chat 桥只发送 `idle/running/succeeded/failed`，不发送 DOM 文本。

## 风险

| 风险 | 影响 | 缓解方案 |
| --- | --- | --- |
| Harness 服务订阅使用 DOM 猜测 | 官方 UI 升级即失效 | 直接注入并订阅 `sessions` 与当前 Session 快照 |
| Chat 页面控件名称变化 | 生成状态漏报 | 同时支持中英文可访问名称，并隔离为可测试脚本 |
| 旧错误在页面打开时触发失败动作 | 宠物无故沮丧 | 首次快照只建立基线，仅响应新错误或运行结束边沿 |
| 成功/失败反馈被立即清空 | 看不到结果动作 | 按对应动画完整周期延时复位 |
| 桥泄露聊天正文 | 隐私风险 | 原生只接收固定枚举，脚本不得传递正文或命令参数 |

## 阶段地图

| 阶段 | 目的 | 退出条件 | 状态 |
| --- | --- | --- | --- |
| S1 | 固化双侧事件契约 | 事件来源、优先级、隐私边界和动画映射明确 | 已完成 |
| S2 | 接入 Harness 官方会话钩子 | 运行、成功、失败边沿驱动 Web 宠物且旧交互不回归 | 进行中 |
| S3 | 接入 Chat WebKit 生成钩子 | 页面生成开始/结束/失败驱动原生宠物且只传枚举 | 进行中 |
| S4 | 构建、部署与实机审核 | 自动检查、签名与两页面真实状态审核通过 | 未开始 |

## 验证策略

- 插件检查覆盖 `sessions` 注入、当前会话/后台任务运行判定、错误边沿和三种命令动画行。
- Core 测试覆盖命令活动到动画的映射与完整周期复位时间。
- Node 脚本模拟 Chat 页面停止按钮出现、消失和错误节点，检查桥只发送固定枚举。
- 运行根检查、生产构建与安装应用签名验证。
- 在本地 Harness 与 Chat 页面检查：运行时持续动作，成功/失败只播放一轮，随后恢复原状态。
