## 原子任务与原子用户故事

### AT-001：创建 Swift Package

用户故事 US-001：作为开发者，我希望只用 macOS Command Line Tools 就能构建客户端，以便快速本地迭代。

#### 范围

- 创建核心 library、SwiftUI executable 和 test target。

#### 验收标准

- Given 已安装 Swift，When 运行 `swift build`，Then 应用成功编译。

#### 验证方式

- `swift build`

#### 完成定义

- 构建退出码为 0。

### AT-002：定义可测试配置

用户故事 US-002：作为维护者，我希望启动地址和命令参数由纯配置生成，以便上游变化时集中修改。

#### 范围

- 定义 loopback URL、端口和 `npx` 参数。

#### 验收标准

- Given 默认配置，When 生成 URL 和参数，Then 分别得到 `http://127.0.0.1:3080` 和官方启动参数。

#### 验证方式

- `./scripts/run_checks.sh`

#### 完成定义

- 配置测试通过。

### AT-003：定位 npx

用户故事 US-003：作为 Mac 用户，我希望应用能识别终端中已安装的 Node.js，以便无需重复配置。

#### 范围

- 搜索当前 PATH 与 Homebrew 常见路径；错误信息列出处理办法。

#### 验收标准

- Given PATH 中存在可执行 `npx`，When 应用查找，Then 返回绝对路径。
- Given 不存在 `npx`，When 应用查找，Then 返回可读错误而不是崩溃。

#### 验证方式

- 单元测试临时 PATH；本机 smoke test。

#### 完成定义

- 正反路径测试通过。

### AT-004：管理服务生命周期

用户故事 US-004：作为用户，我希望项目打开后 Harness 自动可用，并能看到等待或失败原因。

#### 范围

- 启动 `npx --yes @deepseek-ai/dsh web`、轮询 HTTP、收集输出、停止自有进程。

#### 验收标准

- Given 有效工作区和 npx，When 启动，Then 状态从启动中进入运行中或带日志的失败状态。
- Given 服务由应用创建，When 重启或退出，Then 子进程被终止。
- Given 3080 已有 HTTP 服务，When 启动，Then 只附着且不会取得进程所有权。

#### 验证方式

- `swift build`；本机进程与 HTTP smoke test。

#### 完成定义

- 状态、日志和所有权行为可观察。

### AT-005：选择并恢复项目

用户故事 US-005：作为 Codex 用户，我希望从侧边栏选择代码项目并恢复上次目录，以便快速回到工作状态。

#### 范围

- 使用原生目录选择器；通过 UserDefaults 保存路径；切换时重启自有服务。

#### 验收标准

- Given 首次启动，When 选择目录，Then 侧边栏显示项目名和路径并启动服务。
- Given 上次路径仍存在，When 再次启动，Then 自动恢复该路径。

#### 验证方式

- 手工 UI 检查。

#### 完成定义

- 首次选择和恢复路径可用。

### AT-006：内嵌 Harness 工作区

用户故事 US-006：作为用户，我希望在原生应用内完成 Harness 任务，以便不再管理浏览器标签页。
