## AT-101：解析和查询余额

用户故事 US-101：作为 DeepSeek API 用户，我希望看到正确币种和余额拆分，以便判断账户能否继续调用。

### 验收标准

- Given 官方示例 JSON，When 解码，Then 得到可用状态、CNY 110.00、赠金 10.00、充值 100.00。
- Given CNY 与 USD 同时存在，When 选择摘要，Then 优先显示 CNY，详情保留全部币种。
- Given HTTP 401 或非法响应，When 刷新，Then 返回可读错误且不泄露 API Key。

### 验证方式

- `./scripts/run_checks.sh`

## AT-102：安全存储 API Key

用户故事 US-102：作为用户，我希望余额专用 API Key 存在系统 Keychain 中，以便无需每次输入且不会落入项目文件。

### 验收标准

- Given 用户保存 API Key，When 应用重启，Then 可从 Keychain 读取并刷新余额。
- Given 用户移除 API Key，When 再次刷新，Then 状态回到未配置。
- Given 使用 `DEEPSEEK_API_KEY`，When 启动，Then 使用环境变量但不写入 Keychain。

### 验证方式

- 代码审核；实机保存/移除仅由用户执行。

## AT-103：余额状态机

用户故事 US-103：作为用户，我希望区分未配置、刷新中、成功和失败，以便知道金额是否可信。

### 验收标准

- Given 无凭据，When 打开应用，Then 顶部显示“配置余额”。
- Given 请求成功，When 刷新完成，Then 显示金额、币种和更新时间。
- Given 请求失败，When 点击余额入口，Then 显示错误和重试按钮，Harness 仍正常工作。

### 验证方式

- Swift 构建；实机 UI 检查。

## AT-104：配置和详情

用户故事 US-104：作为用户，我希望从余额入口配置、刷新和查看充值/赠金明细，以便在一个位置理解账户余额。

### 验收标准

- Given 未配置，When 点击余额 pill，Then 打开安全配置页。
- Given 已配置且成功，When 点击余额 pill，Then 弹出全部币种及余额拆分。
- API Key 输入框必须为 SecureField，不得回显已保存的 key。

### 验证方式

- 实机 UI 检查。

## AT-105：紧凑工具栏

用户故事 US-105：作为小屏 Mac 用户，我希望原生控制区默认尽可能窄，以便官方 Harness 获得更大的编辑空间。

### 验收标准

- Given 服务运行，When 窗口显示，Then 原生控制区默认宽度为 64pt。
- Given 紧凑状态，Then 新任务、项目、余额、服务状态和日志入口仍可达且有 tooltip。

### 验证方式

- 实机截图和 Accessibility tree。

## AT-106：展开侧栏

用户故事 US-106：作为需要查看项目详情的用户，我希望一键展开完整侧栏，以便查看路径、余额和服务状态。

### 验收标准

- When 点击展开按钮，Then 宽度变为 236pt 且显示现有信息。
- When 再次收起，Then WebView 不重建、当前 Harness 会话不丢失。

### 验证方式

- 实机交互检查。
