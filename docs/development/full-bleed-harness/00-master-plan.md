# 总开发阶段文档：Harness 去外壳化

## 目标

运行态只显示一层完整 Harness 界面：官方 Web UI 直接铺满 macOS 窗口，不再被原生侧栏和原生顶部栏包裹；余额入口无缝出现在 Harness 自身左侧栏。

## 非目标

- 不重写官方 Harness 的会话、导航或编辑器。
- 不修改服务启动、端口、进程树和工作区生命周期。
- 不向 Harness 注入 API Key；余额继续由原生 Keychain/API 客户端读取。

## 当前证据

- 用户截图显示原生 236pt 侧栏、原生 52pt 顶栏与完整官方 Harness UI 同时存在，形成明显的“框里套框”。
- `ContentView.swift` 运行态由 `SidebarView + WorkspaceView + HarnessWebView` 三层组成。
- `HarnessWebView.swift` 已有 WKWebView 协调器，可安全增加受控脚本和消息处理。

## 假设

- “不要框里面还有框”解释为：运行态以官方 Harness 为唯一主界面；原生欢迎、启动和错误页仍可在服务未就绪时使用。
- 余额作为轻量侧栏行嵌入官方左侧栏底部；默认无卡片边框和阴影，详情面板才使用浮层。

## 风险

| 风险 | 影响 | 缓解方案 | 负责人 |
| --- | --- | --- | --- |
| 上游 DOM 结构变化 | 余额入口位置变化 | 注入固定、独立、幂等节点，不依赖 React 类名 | Codex |
| 注入内容覆盖官方设置 | 阻挡操作 | 使用 204px 胶囊并放在设置项上方；保留指针事件范围 | Codex |
| SwiftUI 更新重建 WebView | 会话丢失 | 只更新既有 WKWebView 中的注入节点 | Codex |
| 原生入口消失 | 项目/日志难以访问 | 增加 macOS Harness 菜单与快捷键 | Codex |
