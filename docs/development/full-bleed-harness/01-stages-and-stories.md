## AT-201：单层界面契约

用户故事 US-201：作为用户，我希望窗口看起来就是 Harness，而不是一个桌面壳里再打开一个网页应用。

### 验收标准

- Given Harness 已运行，When 窗口显示，Then 看不到 DS Harness 原生侧栏、项目卡片和原生顶部项目栏。
- Given Harness 未就绪，When 启动或失败，Then 原生状态页仍能解释原因。

## AT-202：全窗 WebView

用户故事 US-202：作为 Harness 用户，我希望官方界面占满可用空间，以便获得与网页版一致的视觉层级。

### 验收标准

- WebView 是运行态根内容，四边直接贴合窗口内容区。
- SwiftUI 状态更新不会重新创建 WKWebView 或丢失当前会话。

### 验证方式

- release 构建；实机截图；交互检查。

## AT-203：嵌入式余额

用户故事 US-203：作为 API 用户，我希望余额仍然可见，但它应属于 Harness 左侧栏，而不是另起一层外壳。

### 验收标准

- 余额胶囊位于 Harness 左侧栏底部、设置项上方。
- 未配置、加载、成功、失败四态均有短文本和状态点。
- 点击余额胶囊只向原生层发送固定 `open` 消息，不携带 API Key 或余额 JSON。

### 验证方式

- 代码审核；WKWebView 实机交互。

## AT-204：原生操作可达

用户故事 US-204：作为桌面用户，我希望移除外层控件后仍能切换项目、查看日志和配置余额。

### 验收标准

- macOS 菜单提供选择项目、新任务、刷新、余额设置和日志。
- 不向 Web UI 叠加新的原生导航栏。

## AT-205：完工验证

用户故事 US-205：作为产品负责人，我希望用真实运行截图确认只剩一层主界面。

### 验收标准

- checks、build、plist 和 codesign 通过。
- 截图展示单层 Harness 和左侧栏余额入口。

## AT-206：明确收起余额明细

用户故事 US-206：作为用户，我希望展开余额后能明确关闭，并在执行设置或刷新后自动收起，以免明细一直遮挡左侧栏。

### 验收标准

- 明细右上角显示独立关闭按钮。
- 再次点击余额摘要、点击明细外部或点击关闭按钮均可收起。
- 点击配置 API Key 或刷新后，明细立即收起。
- 每次页面重新载入时默认保持收起。

## AT-207：直观配置 API Key

用户故事 US-207：作为用户，我希望余额明细中直接看到“配置 API Key”，以便无需寻找系统菜单。

### 验收标准

- 明细底部提供文字完整的“配置 API Key”主按钮。
- 点击后打开现有原生安全配置页，使用 SecureField 和 macOS Keychain。
- 已保存 Key 不回显；保存后自动刷新余额。
- 即使存在 `DEEPSEEK_API_KEY` 环境变量也显示输入框；钥匙串凭据优先，移除后回退到环境变量。

## AT-208：余额跟随官方侧栏折叠

用户故事 US-208：作为使用紧凑 Harness 侧栏的用户，我希望余额入口同步缩成图标，以免折叠侧栏后仍有一张宽卡片遮挡主界面。

### 验收标准

- Given 官方侧栏展开，Then 余额显示状态点、金额和说明。
- Given 官方侧栏折叠，Then 余额入口缩为与侧栏图标一致的 40×40pt 按钮，只显示钱包图标与状态点。
- When 从折叠切换为展开或反向切换，Then 余额样式在同一页面内自动更新，不重载会话。
- Given 紧凑余额按钮，When 点击，Then 仍可展开余额详情和进入 API Key 配置。

### 实现约束

- 优先通过官方侧栏开关的可访问名称判断，不依赖压缩 CSS 类名。
- 使用 MutationObserver 监听按钮属性变化，并限制观察范围与更新频率。

## AT-209：紧凑余额图标中心线对齐

用户故事 US-209：作为重视界面一致性的用户，我希望余额图标与官方侧栏图标居中对齐，以便折叠栏看起来属于同一套设计。

### 验收标准

- Given 官方折叠侧栏约 52pt 宽、余额按钮 40pt 宽，Then 紧凑态使用 6pt 左边距。
- Given 用户局部截图，When 对比鲸鱼、新会话、搜索、余额和设置，Then 图标视觉中心位于同一条竖直中心线，误差不超过 2px。
- 展开态继续使用 12pt 左边距，不受该修正影响。

## AT-210：展开态轻量侧栏行

用户故事 US-210：作为使用展开侧栏的用户，我希望余额入口和“设置”属于同一套菜单样式，而不是一张单独悬浮的卡片。

### 验收标准

- Given 官方侧栏宽度可能随窗口变化，Then 余额入口动态使用“侧栏宽度减 24pt”，始终保留 12pt 两侧留白。
- Given 余额入口未悬停，Then 不显示独立边框、实体背景、阴影或模糊材质。
- When 指针悬停，Then 只显示与官方菜单一致的轻微圆角底色。
- 状态点、金额和说明与下方设置行对齐；余额详情仍使用独立浮层，折叠态继续保持 6pt 左边距和 40×40pt 尺寸。

## AT-211：公开发布安全收口

用户故事 US-211：作为发布者，我希望源码公开时不会误带本地缓存或扩大 API Key 暴露面，并能明确知道正式分发前的剩余风险。

### 验收标准

- `.smoke-npm-cache/` 与 `.test-dsh-home/` 被 Git 忽略，普通 `git add .` 不会收录本地测试状态或 npm 日志。
- `DEEPSEEK_API_KEY` 只供原生余额客户端使用，不继承给 `npx`/Harness 子进程。
- 发布审核记录无硬编码密钥命中，并明确列出截图隐私、许可证、品牌、版本锁定、Developer ID 签名与公证风险。

## AT-212：统一余额与设置图标网格

用户故事 US-212：作为使用展开侧栏的用户，我希望余额和设置使用相同的图标列与文字起点，而不是用小状态点假装成菜单图标。

### 验收标准

- 余额使用固定 18pt 的 `¥` 图标槽，图标中心与设置齿轮中心位于同一竖线。
- 状态点缩为图标右上角徽标，不再独占一列或影响文字布局。
- 展开态图标左缘约为 16pt、中心约为 25pt，金额文字起点约为 39pt，与设置行误差不超过 1px。
- 折叠态仍保持 40×40pt 点击区和约 26pt 的整栏中心，不改变详情与 API Key 交互。

## AT-213：精简欢迎页入口

用户故事 US-213：作为首次进入 Harness 的用户，我希望主按钮只显示“进入”，以便界面更简洁。

### 验收标准

- 欢迎页主按钮显示“进入”。
- “进入”按钮使用简洁文案与直接进入图标。
- 菜单中的“选择项目…”及 `⌘O` 保持不变。

## AT-214：无需选择文件夹直接进入

用户故事 US-214：作为只想立即体验 Harness 的用户，我希望点击“进入”后直接启动，而不是先选择文件夹。

### 验收标准

- 点击“进入”不会打开 `NSOpenPanel`。
- 首次进入时自动创建并使用 `Application Support/app.dsharness.desktop/Workspace`，不授权整个个人目录。
- 默认工作区会作为最近工作区保存，后续启动自动恢复。
- 菜单“选择项目…”和 `⌘O` 继续用于切换到用户自己的代码目录。
- 默认目录创建失败时显示明确错误，不静默停留在欢迎页。
